How this is calculated

Entropy. We estimate the character pool the password draws from (lowercase, uppercase, digits, symbols) and compute entropy = length × log2(pool size), the standard back-of-envelope measure of how many guesses a brute-force search would need on average.

Penalties. Raw entropy overstates real strength when a password is a dictionary word, a keyboard walk (qwerty), a repeated run (aaaa), or a sequence (1234, abcd) — these collapse the effective search space, so we detect them and cap the score accordingly.

Crack time. "Offline" assumes an attacker who has stolen a password database and is hashing guesses on GPUs at roughly 10 billion/sec — realistic against a fast, unsalted hash. "Throttled online" assumes a login form that rate-limits to about 10 attempts/sec, showing why where a hash is checked matters as much as the password itself.

Storage note. This demo hashes with SHA-256 purely to compare passwords without keeping plaintext around. SHA-256 is fast, which is exactly wrong for password storage — real systems use slow, salted, memory-hard functions like bcrypt, scrypt, or Argon2, which turn each guess into a costly operation and make offline brute-forcing far slower than the number above.
